How Sijil sits in the network

Sijil is one container between the entity's agents and its model server. Agents call Sijil instead of the model. Sijil checks each call against the entity's policy, forwards or blocks it, and seals a signed record of the decision. Nothing leaves the entity's network.

AI agentsOpenAI-compatible clients
→
Sijilpolicy check, signed record per call
→
Model serverself-hosted, e.g. vLLM, llama.cpp
SOC / SIEMreceives every record as CEF over syslog
Auditorsverify an export offline with the free verifier
HSM (optional)holds the Ed25519 signing key
2

Before you start

  • Host: a Linux VM with Docker or Podman. One container, one worker; 2 vCPU and 4 GB RAM are enough for a pilot.
  • Model server: self-hosted, OpenAI-compatible (/v1/chat/completions), reachable from the host, with bearer-token auth or none.
  • Model weights on disk: the GGUF file the model server loads, readable from the Sijil host. Sijil fingerprints it (SHA-256) to prove which model answered.
  • An admin token: a random string of 32 or more characters, kept in the entity's secret store.
  • A reverse proxy with the entity's SSO in front of Sijil's read pages (see step 7).
  • Optional: an HSM with a PKCS#11 library and an Ed25519 key; a SIEM syslog endpoint (TCP preferred).

Build the offline bundle

On a connected machine with Docker, from a clean checkout of main:

scripts/bundle_offline.sh
# prints dist/sijil-<sha>.tar.gz

The script refuses to build from uncommitted changes, so the image tag always matches a real commit. The bundle holds the image, policy.yaml, the verifier, the SIEM forwarder, INSTALL.txt and this guide. Carry it to the site on approved media.

4

Install on site

  1. Load the image

    tar xzf sijil-<sha>.tar.gz && cd sijil-<sha>
docker load < sijil-image-<sha>.tar.gz        # or: podman load -i sijil-image-<sha>.tar.gz

  2. Fingerprint the approved model

    sha256sum /srv/models/<model-file>.gguf

    Put the result in policy.yaml as sha256:<hex> under the approved_models rule. Agents must request the model by a name the weights file starts with: model llama-3.2-3b-instruct matches Llama-3.2-3B-Instruct-Q4_K_S.gguf (case-insensitive).

  3. Edit the policy

    Keep it in its own directory and mount the directory, so edits are seen without restarting the container.

    mkdir -p /etc/sijil && cp policy.yaml /etc/sijil/

policy_id: gov-assistant
version_label: "2026-10-11.1"
approval_ref: "APR-0147"            # the entity's approval reference
node:
  id: "auh-node-01"
  region: "AE-AZ"
rules:
  - id: residency
    type: region_allowlist
    allow: ["AE-AZ", "AE-DU"]
    mode: enforce
  - id: approved_models
    type: model_allowlist
    allow_digests: ["sha256:<hex from step 2>"]
    mode: enforce
  - id: sensitive_terms
    type: keyword_flag
    terms: ["emirates id", "passport number"]
    mode: record

    enforce blocks a call that matches; record lets it through and flags it on the record. Rule ids upstream_error, halted and resumed are reserved.

  4. Run Sijil

    docker network create sijil-net
docker run -d --name sijil --network sijil-net --restart unless-stopped \
  -p 8000:8000 \
  -v /etc/sijil:/config:ro \
  -v /srv/models:/models:ro \
  -v sijil-data:/data \
  -e SIJILL_ADMIN_TOKEN=<admin token> \
  -e LMSTUDIO_BASE_URL=http://<model-server>:<port>/v1 \
  -e LM_API_TOKEN=<model server token, if any> \
  -e SIJILL_MODEL=<default model name> \
  sijil:<sha>

    All state (records, signing key or public key, digest cache, halt flag) lives in the sijil-data volume. Back it up like any database volume.

    With an HSM, add the vendor library and the four PKCS#11 settings:

      -v /opt/vendor/lib:/opt/pkcs11:ro \
  -e SIJILL_PKCS11_MODULE=/opt/pkcs11/<library>.so \
  -e SIJILL_PKCS11_TOKEN=<token label> \
  -e SIJILL_PKCS11_KEY=<key label> \
  -e SIJILL_PKCS11_PIN=<user PIN> \

    If the HSM is configured but unreachable, Sijil refuses to start. It never falls back to a key file.

  5. Check it is healthy

    curl -s http://localhost:8000/api/policy   # "admin_auth": "token", your policy_id and region
curl -s http://localhost:8000/api/verify   # "ok": true

    From a repo checkout, scripts/smoke_container.sh sijil:<sha> runs the full container check, including one real model call.

  6. Point the agents at Sijil

    Set each agent's OpenAI base URL to http://<sijil-host>:8000/v1. No agent code changes. Streaming (stream: true) is supported. Blocked calls return HTTP 403 with the rule ids and the record's sequence number.

  7. Put the read pages behind SSO

    The dashboard / and /api/records, /api/policy, /api/verify, /api/report have no login of their own in this build. Publish them only through the entity's reverse proxy with SSO. Agents need only /v1/chat/completions; admin calls need the admin token.

  8. Connect the SOC

    Run the forwarder from the same image, on the same network and volume:

    docker run -d --name sijil-siem --network sijil-net --restart unless-stopped \
  -v sijil-data:/data --entrypoint python sijil:<sha> \
  scripts/siem_forward.py --url http://sijil:8000 --sink <siem-host>:514 --state /data/siem_state

    TCP is the default and does not drop records; add --udp only for a UDP-only receiver. Delivery is at-least-once: after a crash, up to one page may be sent twice. Blocks arrive at CEF severity 8, flags at 5, everything else at 3.

Day-to-day operation

Admin calls below assume TOKEN holds the admin token and S the Sijil URL, for example S=http://localhost:8000.

Daily health check

curl -s $S/api/verify

"ok": true means every record's hash, signature and chain link checks out. Any FAIL seq=N is an incident: see Troubleshooting.

Emergency stop

curl -s -X POST $S/api/admin/halt \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"halted": true}'

Every call is blocked and sealed with halted; streams in progress are cut off. The halt survives a restart. Resume with {"halted": false}. Both actions are on the record.

Change the policy

# edit /etc/sijil/policy.yaml, then
curl -s -X POST $S/api/admin/policy/reload \
  -H "Authorization: Bearer $TOKEN"

Any change to the file is sealed as a policy_change record naming the rules whose mode changed. A malformed file is rejected and the old policy stays in force.

Record a region move

curl -s -X POST $S/api/admin/node/region \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"region": "AE-DU"}'

Use when the node is moved or failed over. If the new region is not allowed, the residency rule blocks calls from then on.

Export for an auditor

docker run --rm -v sijil-data:/data --entrypoint sqlite3 sijil:<sha> \
  /data/sijill.db ".backup /data/export.db"
docker run --rm -v sijil-data:/data --entrypoint cat sijil:<sha> /data/export.db > export.db
docker run --rm -v sijil-data:/data --entrypoint cat sijil:<sha> /data/node.pub > node.pub

Always export with .backup: a plain copy of a live database can be torn and fail verification. Hand over export.db, node.pub and the verifier/ folder.

Auditor verifies, offline

python3 verifier/sijill_verify.py --db export.db --pubkey node.pub

Needs only Python 3 and the cryptography package. Prints PASS records=N or FAIL seq=N <reason>. It shares no code with Sijil, so the auditor does not have to trust us.

Audit report (PDF)

curl -s "$S/api/report?from=2026-10-01T00:00:00Z&to=2026-10-31T23:59:59Z" \
  -o sijil-report.pdf

Decisions, rule hits and the verification result for the period. from and to are optional.

Watch the SOC feed

docker ps --filter name=sijil-siem
docker logs --tail 20 sijil-siem
docker run --rm -v sijil-data:/data --entrypoint cat sijil:<sha> /data/siem_state

The forwarder retries through outages and resumes from its saved position. Each failed attempt logs one line naming the error, the attempt count and the retry delay; a healthy forwarder logs nothing. If the SIEM shows a gap, read the log, then check that the saved sequence number keeps rising.

Upgrades and key changes

  • Upgrade: load the new bundle's image, then replace the container with the same volume, network and settings. The chain continues; run the health check after.
  • Upgrading from an M1 install (v2 schema): the new image refuses to open an M1 database until it is migrated. Stop and remove the old container, take a backup with the .backup command from the export step, then run docker run --rm -v sijil-data:/data --entrypoint python sijil:<tag> scripts/migrate_v2.py /data/sijill.db (safe to repeat). Start the new container and run the health check.
  • Moving to an HSM: Sijil refuses to start if the HSM key differs from the key that signed the existing records. Export and archive the old chain with its node.pub, then start the HSM-backed node on a new volume.
  • New model version: fingerprint the new weights, add the digest to approved_models, reload the policy. Remove the old digest when the old model is retired.

Troubleshooting

SymptomCause and fix
Admin call returns 503SIJILL_ADMIN_TOKEN is not set on the container. Set it and recreate the container.
Admin call returns 401Wrong or missing Authorization: Bearer header.
Every call 403, hit approved_modelsThe model's fingerprint is not in the policy, or Sijil cannot find the weights: check the /models mount and that the model name matches the start of the GGUF file name.
Every call 403, hit residencyThe node's region is not in the allowlist. Check /api/policy for the current region.
Every call 403, hit haltedAn operator halted the node. Resume with {"halted": false} when cleared.
502 with upstream_errorThe model server is down or returned something invalid. The failed call is still sealed.
Container exits at start, PinIncorrectWrong SIJILL_PKCS11_PIN.
Container exits at start, "signed by a different key"HSM key does not match the chain in the volume. See Upgrades: start a new volume.
Verifier: FAIL seq=N content altered or signature invalidRecord N was changed after sealing, or the export is torn. Re-export with .backup; if it still fails, treat it as a security incident and preserve the volume.

Known limits of this build

Read these before a security review.

  • The approved-model check needs the weights on disk. A remote or API-only model gets no fingerprint and is blocked by an enforcing approved_models rule. API model fingerprints come in the next milestone.
  • Only /v1/chat/completions is proxied. Tool-call policy (the MCP guard) comes in the next milestone.
  • Upstream auth is a bearer token. Azure OpenAI's own api-key header is not supported yet.
  • Read pages have no login of their own; they must sit behind the entity's SSO proxy.
  • Streamed answers are sealed after delivery. If signing fails mid-stream (for example the HSM drops), that answer was delivered but not sealed.
  • A non-streamed call already sent to the model when a halt lands completes and is sealed after the halt record. A halted stream is sealed block with halted and upstream_error even though part of it was delivered.
  • Records prove nothing was changed after sealing. They do not prove the host itself was honest; hardware attestation is on the roadmap.
